The LRM foundation (500M params) demonstrated that a single large transformer can replace per-shape optimization entirely. TripoSR inherits this architecture and adds training improvements (better data rendering, channel upsampling) to achieve state-of-the-art quality.

1
Image Encoder

DINOv1 Vision Transformer

The input image (224×224) is split into a 14×14 grid of 16px patches. Each patch is linearly projected to a 768-dimensional token.

The ViT processes all 196 patch tokens through 12 transformer layers with self-attention. Each token "looks at" every other token — this is how the model understands spatial relationships across the image.

DINOv1 was pretrained with self-supervised learning (no labels needed). TripoSR chose it over DINOv2 because v1 produced better 3D reconstruction quality in their ablation studies.

Key insight: The 196 output tokens encode rich geometric priors — edges, surfaces, depth cues — learned entirely from unlabeled images via self-distillation.

Triplane Decoder

3D Feature Planes

The transformer decoder takes the 196 image tokens and produces a triplane representation: three orthogonal 2D feature maps aligned to the XY, XZ, and YZ planes.

To query a 3D point (x,y,z), we project it onto each plane, bilinearly sample the feature, and sum the three feature vectors. This aggregated feature is fed to a small MLP that predicts density and color.

Triplanes are memory-efficient: instead of a dense 3D voxel grid (N³ memory), triplanes use only 3×N² — a massive reduction that makes high resolution feasible.

Triplane resolution: 3 × 64×64 × 40 channels = 491K parameters
Equivalent voxel grid: 64³ × 40 = 10.5M parameters (21× more)
3a
Volume Rendering

NeRF Ray Marching

During training, TripoSR renders images via neural radiance field (NeRF) volume rendering. For each pixel, a ray is cast into the scene.

Along each ray, we sample N points and query the triplane MLP for density (σ) and color (c) at each sample. The final pixel color is computed by alpha-compositing front-to-back:

C = Σ Tᵢ · αᵢ · cᵢ   where   αᵢ = 1 - exp(-σᵢ · δᵢ)

Tᵢ is the accumulated transmittance (how much light reaches sample i), and δᵢ is the distance between consecutive samples.

At inference time, NeRF rendering is NOT used — the triplane is decoded directly to a mesh via marching cubes. NeRF is only the training supervision signal.

Mesh Extraction

Marching Cubes

Once trained, the density field is evaluated on a regular 3D grid. The marching cubes algorithm walks through each cell and classifies the 8 corners as inside (density > threshold) or outside.

Each of the 256 possible corner configurations maps to a predefined set of triangles that approximate the surface crossing through that cell. The triangles stitch together into a watertight mesh.

The algorithm processes cells independently — making it trivially parallelizable on GPU. TripoSR uses FlexiCubes (a differentiable variant) for better mesh quality near thin features.

Marching cubes was introduced by Lorensen & Cline (1987). Despite being nearly 40 years old, it remains the dominant algorithm for extracting meshes from implicit fields.

TripoSG: The Next Generation

TripoSG (2025) replaces the NeRF density field with a Signed Distance Function (SDF) and uses rectified flow for the 3D generative model. Key improvements:

  • SDF representation — smoother surfaces, better thin structures
  • Normal + Eikonal losses — enforce geometric consistency
  • 3D VAE — learned latent space for the triplane
  • Rectified flow — faster, more stable training than diffusion
